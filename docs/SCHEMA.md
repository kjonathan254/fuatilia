# Capture Record Schema

One JSON object per line in `data/captures.jsonl` (JSON Lines: each line is a complete,
independent record — safe to append, merge and diff with git).

## Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | auto | Slug generated by the CLI from advertiser+platform+date |
| `captured_at` | ISO date | auto | Day you browsed the library — shown in the viewer as provenance |
| `advertiser` | string | ✅ | Exact brand name as shown in the library |
| `platform` | string | ✅ | `meta` \| `google` \| `tiktok` |
| `country` | string | ✅ | ISO-3166 alpha-2, e.g. `KE` |
| `page_id` | string \| null | optional | Meta page ID when known (from the library URL) |
| `ad_start` | ISO date | recommended | Start date printed on the ad card — feeds the tenure signal |
| `first_seen_by_us` | ISO date | auto | First Fuatilia capture of this ad |
| `active_versions` | number | recommended | Active variants of this ad concept — may include aspect-ratio, language or placement variants, not just new hooks. Feeds the creative-experimentation signal |
| `active_ad_count` | number | recommended | **The advertiser's total active ads on this platform**, exactly as the library's advertiser page shows it. Feeds the scale band. Never infer it from version counts or from how many rows you saved |
| `capture_method` | string | auto | `manual` (default) \| `auto` — how the row was captured |
| `creative_type` | string | optional | `video` \| `image` \| `carousel` \| `search` \| `other` |
| `offer` | string | optional | The headline offer, in the advertiser's own words (short quote only) |
| `landing_url` | string | optional | Where the ad's CTA goes |
| `landing_headline` | string | optional | The H1 on the landing page (structure reference, not for copying) |
| `library_url` | string | optional | Direct link back to the ad/advertiser in the public library |
| `source` | string | optional | Which surface: `manual_capture` (default) \| `meta_api` \| `google_atc` \| `tiktok_cc` |
| `tags` | string[] | optional | Free tags: `isp`, `promo`, `electronics`, `diaspora`… |
| `example` | boolean | optional | `true` on demo rows shipped with the repo — excluded from real digests |
| `notes` | string | optional | Anything future-you will thank you for |

## Example (real shape, fictional advertiser)

```json
{"id":"demo-isp-ltd_meta_2026-10-26_a1","captured_at":"2026-10-26","advertiser":"Demo ISP Ltd","platform":"meta","country":"KE","page_id":null,"ad_start":"2026-07-02","first_seen_by_us":"2026-10-26","active_versions":4,"active_ad_count":14,"capture_method":"manual","creative_type":"video","offer":"Free router + installation this month","landing_url":"https://example.co.ke/deal","landing_headline":"Home fibre from KSh 2,999/mo","library_url":"https://www.facebook.com/ads/library/?id=000000000000000","source":"manual_capture","tags":["isp","promo"],"example":true,"notes":"Fictional demo row — replace with your captures"}
```

## Rules of the road

1. One ad card = one line. If the advertiser has 30 active ads, capture the 5 that matter
   (newest, longest-lived, most versions) and note the total in `notes`.
2. `active_versions` counts **variants of the same ad concept**, not the advertiser's
   whole catalogue — and variants are not always hooks (they can be aspect ratios,
   languages or placements). That distinction is what makes the creative-experimentation
   signal meaningful.
3. `active_ad_count` is the advertiser's **total active ads on that platform**, read off
   the library's advertiser page. The scale band is computed from this field and from
   nothing else — never from version counts, never from how many rows you saved.
4. Quote offers sparingly and for reference only — you are taking notes, not republishing.
5. `example: true` rows are ignored by `fuatilia digest` once you start capturing real ads.
