01 What your agent learns to do

Six parts, one loop.

The skill is a complete playbook. Parts A–D are one-time setup; Part E is the weekly cycle your agent repeats; Part F is the Monday pipeline that runs itself.

Part A

One-time setup

Clone (zero dependencies), run the idempotent Supabase migration, verify the CLI, configure the portal with the anon public key, set repository secrets.

Part B

Telegram bot

@BotFather → /newbot → press Start → read the chat ID from getUpdates → two repository secrets. Test locally, then from Actions. ~15 minutes.

Part C

WhatsApp delivery

Meta Cloud API: app, phone number ID, system-user token — and the registered fuatilia_weekly_intel template, the only compliant way to business-initiate a weekly brief.

Part D

Client onboarding

Client self-signs up on the portal (a trigger creates their profile + subscription), creates a brief, you wire two secrets. A shared Telegram group keeps both sides honest.

Part E

The weekly capture loop

Browse the public ad libraries for Kenya (no login, no API), record each card with fuatilia add — verbatim offer, start date, library URL — then check, score, push.

Part F

The Monday pipeline

GitHub Actions: push → digest → snapshot → deliver → report (deterministic facts + guardrailed AI) → per-customer templates → heartbeat → archive. Every stage skips itself honestly.

03 The weekly loop

Capture → validate → push → Monday.

Kenyan commercial ads are not in any API — Meta’s Ad Library API covers EU + issue ads only. So the evidence layer is deliberate, human (or agent-driven browser) capture from the login-free public libraries. ~20–30 minutes per client per week.

StepCommandWhat it does
Browsefacebook.com/ads/library → country Kenya · adstransparency.google.com → region KenyaPick active cards in your sector. Copy the offer text verbatim, the start date, the card URL.
Recordnode bin/fuatilia.js add --advertiser "…" --platform meta --start … --offer "…" --library "…"One row per card in data/captures.jsonl — real captures only.
Validatenode bin/fuatilia.js check then scoreSchema-check every row; print tenure, signals and scale bands.
Pushnode bin/fuatilia.js push --brief <uuid> --source manualBrief-linked evidence to the platform (or let Monday’s workflow push automatically).
MondayFuatilia AdWatch workflow — 09:00 NairobiDigest + snapshot + report + delivery, then a heartbeat commit as public proof.

Why the signals are honest

Scale bands read active-ad counts, never variant counts. A 90-day-old ad is a persistence signal, not a performance verdict. Every output carries the caveat: signal, not proof. Fuatilia classifies — you decide.

04 Telegram delivery

A report bot in six steps.

The easiest channel — zero infrastructure, and it is how the first real client report was delivered and confirmed.

  1. Create the bot with @BotFatherSend /newbot in Telegram. Pick a name (e.g. Fuatilia Digest) and a username ending in bot. BotFather replies with the token — the bot’s password. Never commit it; /revoke mints a new one if it leaks.
  2. Press Start in the bot’s chatBots cannot message you first. Skipping this makes every later send fail with chat not found.
  3. Get your chat IDOpen https://api.telegram.org/bot<TOKEN>/getUpdates in a browser and read "chat":{"id":…}. For groups: add the bot, disable privacy mode, use the negative group ID.
  4. Add two repository secretsFUATILIA_TELEGRAM_BOT_TOKEN and FUATILIA_TELEGRAM_CHAT_ID under Settings → Secrets and variables → Actions.
  5. Test from your machineFUATILIA_TELEGRAM_BOT_TOKEN=… FUATILIA_TELEGRAM_CHAT_ID=… node bin/fuatilia.js deliver
  6. Test from the cloudActions → Fuatilia AdWatch → Run workflow. From then on the digest arrives every Monday 09:00 Nairobi — and failures alert the same chat.
05 WhatsApp delivery

Official Cloud API, template-first.

Free-form WhatsApp text is only deliverable inside a 24-hour customer-service window — so a scheduled weekly brief must go as an approved template. The skill walks your agent through the whole registration.

  1. Create the Meta appdevelopers.facebook.com → Create App → Business → add the WhatsApp product. Note the test phone number ID and temp token.
  2. Verify recipientsTest mode allows up to 5 verified numbers — enough for a personal weekly brief.
  3. Add the secretsFUATILIA_WHATSAPP_TOKEN (system-user token), FUATILIA_WHATSAPP_PHONE_ID, FUATILIA_WHATSAPP_TO (number, country code, no +).
  4. Register the templateMeta Business Manager → Message templates → name fuatilia_weekly_intel, category Marketing, language en — the exact five-parameter body is in the skill file and docs/DELIVERY.md §5. Approval: minutes to 48h.
  5. Let deliver-reports do the sendsEvery active WhatsApp brief gets its personalised template message; each send is recorded in the platform’s deliveries table. Reply-STOP numbers must be opted out before the next send.

Pragmatic shortcut

Not ready for Meta Business Manager? Deliver to Telegram and forward — or bridge any automation tool with FUATILIA_WEBHOOK_URL (POSTs the full markdown digest as JSON).
